## hecto-api

Lightweight offline-first desktop API client replacing Postman/Bruno. Wails v2 (Go backend, native webview), Vue 3 frontend, file-based storage (JSON/YAML). Planning in `docs/`, BMad output in `_bmad-output/`.

## Policy

- Never push to main or develop directly; feature branches → MR into develop, develop → merge into main.
- Follow Semantic Versioning for all releases.
- Never hand-edit files under `_bmad-output/` — they are generated by BMad skills.
- Skill directories (`.agent/skills/`, `.agents/skills/`, `.claude/skills/`, `.kiro/skills/`) are gitignored — never commit them.

## Where things are

- Product brief and planning docs: `docs/`
- BMad configuration: `_bmad/config.toml`
- Generated artifacts: `_bmad-output/`

## Conventions that differ from defaults

- Storage is always file-based JSON/YAML on disk — no database, no cloud sync, no login.
- Money-style numeric values (response time, size) use integers, not floats.

## Tooling (frontend)

- Package manager is **bun** (see `projects/wails.json`, `projects/frontend/bun.lock`). Always use `bun install` / `bun run <script>` — never `npm`, `npx`, `yarn`, or `pnpm`, even if a spec says `npm run ...`.
- Shell default Node is v18, but the project needs Node 24 (`.nvmrc`). Before running any frontend/Node/bun/wails command, run `source ~/.nvm/nvm.sh && nvm use` in the project root (in the same shell invocation as the command).

## Git rules (OVERRIDES policy above)

- **Branching**: Story work (`/bmad-build`) is done DIRECTLY on the `develop` branch. Do NOT create feature branches. Do NOT ask the user which branch to use. Ignore the "Never push to develop" policy for story work.
- **Safety**: Never run `git commit`, `git push`, or any version-control write operation without explicit user approval. Always ask first.

## Review gate (bmad-build)

**Purpose:** The gate between step-03 (implement) and step-04 (review) exists so the human can switch to a different model before review. Review is still performed by the agent (via review subagents, step-04) — NOT by the human. The gate is a pause, not a hand-off of the review work.

- **MANDATORY HALT**: After step-03 finishes and verification passes, you MUST:
  1. Set sprint-status to `review` (spec `in-review`).
  2. Tell the human the story is at the review gate and they can switch model.
  3. **STOP / HALT**. Do NOT start step-04 in the same turn. NEVER self-review inline and mark as done in the same turn.
  *(Exception: For unattended `bmad-build-auto` runs, skip this gate and proceed directly to step-04.)*
- **Resuming**: When the human resumes and tells you to proceed, run step-04 using **subagents**. Run the three review layers (blind-hunter, edge-case-hunter, verification-gap) via subagents, triage findings, and apply patches.
- Never set the spec to `done` until review findings are triaged.
