Công cụ CLI cho AI Agent tích hợp vào hecto-api

Thực thi HTTP Request headless (4-Tier Variable Resolution, Auth Inheritance, Script Runner) và CRUD Collection/Env/Folder/Request đồng bộ an toàn với Wails Desktop.

🔒 Các quyết định đã khóa (Locked Decisions)

1. Binary CLI độc lập trong cùng Repo (projects/cmd/hecto/main.go)

Biên dịch ra file thực thi riêng hecto (thuần Go, không phụ thuộc Wails/GTK/WebKit). Người dùng hoặc CI có thể cài lẻ chỉ CLI mà không cần cài Desktop App, trong khi mã nguồn tái sử dụng 100% các package Go sẵn có (model, storage, service, slug).

2. Shared TS Execution Engine qua //go:embed + goja

Giữ nguyên 1 bản code TypeScript duy nhất cho 4-Tier Variable Resolution, Auth Inheritance, Request Builder và Script Runner tại frontend/src/utils/ để Vue gọi đồng bộ 0ms trên UI. Khi build, đóng gói thêm headless-engine.js (~25KB) nhúng vào Go và thực thi trên goja (pure Go JS engine). Tầng Go chỉ tiêm polyfill Base64, gọi ExecutorService.Send và lưu các biến/auth bị script mutate xuống đĩa.

3. Giao thức Stateless CLI (--json) + Tự khám phá qua hecto agent-guide

Dùng CLI stateless (mỗi lệnh đọc mới từ đĩa rồi thoát) kèm cờ --json trả về chuẩn model.Result. Lệnh hecto agent-guide in trực tiếp nội dung chuẩn SKILL.md (nhúng sẵn trong binary) ra stdout và được nhắc ngay ở dòng đầu của hecto --help để mọi AI Agent tự đọc hoặc tự import vào thư mục skill riêng.

4. Ma trận lệnh trực giao hecto <entity> <verb>

Bao phủ đủ 4 thực thể (collection, env, folder, req) với các động từ tường minh (list/tree, get, create, update, delete, move), cùng 3 lệnh top-level (hecto run, hecto import, hecto agent-guide). Lệnh create nhận trọn bộ cấu hình trong 1 bước; lệnh update thực hiện Read-Merge-Write (patch) để tránh mất dữ liệu; hỗ trợ định danh bằng cả UUID lẫn đường dẫn tên.

5. Đồng bộ 3 lớp + Nút Smart Reload riêng biệt trên Desktop UI

Giữ Atomic Write (.tmp-* → fsync → rename); sửa FindByUUID tự kiểm tra Exists(path) để tự chữa lành cache RAM và bỏ IndexRebuild quét lặp trong GetTree. Trên UI: không reload toàn cửa sổ và không tự động reload ngầm gây lag; cung cấp nút Reload dữ liệu riêng (kèm chấm báo hiệu khi fsnotify phát hiện thay đổi ngoài) để thực thi Smart Data Reload (giữ nguyên expandedFolders, đồng bộ tabStore, bảo vệ tab đang gõ dở isDirty).

⚡ Các điểm mù thực tế đã phát hiện và vượt qua (Cracks Survived)

Điểm mù 1: 4-Tier Variable, Auth Inheritance & Script Runner nằm 100% ở Vue Frontend

Trái với giả định ban đầu rằng Go Backend đã có sẵn bộ máy này, ExecutorService.Send ở Go chỉ bắn HTTP thô, còn 2.300 dòng xử lý biến/auth/script nằm ở frontend/src/utils/*.ts và được các component Vue gọi đồng bộ (computed) trên từng phím gõ. Giải pháp nhúng bundle TS vào goja giải quyết triệt để mà không phải viết 2 bộ code song song.

Điểm mù 2: Lỗi Stale Index trong FileSystem.FindByUUID & Quét đĩa kép trong GetTree

FindByUUID trả về đường dẫn từ map RAM mà không kiểm tra Exists(path), sẽ gây lỗi NOT_FOUND trên UI khi CLI di chuyển file. Đồng thời GetTree gọi cả IndexRebuild lẫn buildTree làm đọc toàn bộ file JSON 2 lần.

Điểm mù 3: Bẫy Auto-Save 800ms đè dữ liệu trong requestStore.ts

UI có bộ đếm scheduleAutoSave(800ms). Nếu không kiểm tra trạng thái isDirty và không tách nút Smart Data Reload riêng, UI và CLI có thể ghi đè lẫn nhau hoặc gây khựng giao diện.

🚫 Các phương án đã bác bỏ & Lý do (Rejected Options)

Viết lại toàn bộ bộ máy biến 4 tầng & Auth bằng Go thuần rồi xóa bản TS

Không thể xóa bản TS vì VariableHighlighter.vue và VariableHoverPopover.vue cần chạy đồng bộ tức thì trên UI; giữ cả bản Go và bản TS sẽ dẫn tới lệch hành vi (dual-engine drift).

Tách CLI ra một Project/Repo riêng không liên quan

Phải viết lại từ đầu toàn bộ model, storage, slug, service và tự đồng bộ thủ công khi nâng cấp cấu trúc file JSON, nguy cơ cao gây mất dữ liệu (schema drift).

Làm MCP Server (hecto mcp) làm giao thức chính hoặc hardcode đường dẫn skill install

MCP tiêu tốn hàng nghìn tokens cố định ở mọi lượt hội thoại và giữ state trong RAM dễ bị lệch index; hardcode đường dẫn skill không thể bao phủ hết mọi AI Agent trên thị trường.

Tự động reload toàn bộ cửa sổ hoặc reload liên tục mỗi 200ms/on-focus

Gây khựng giao diện (lag) khi Agent chạy chuỗi lệnh liên tiếp và tạo trải nghiệm UX giật cục không mong muốn.
