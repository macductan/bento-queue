Example Request cho hecto-api

Rèn bài toán, kiểm thử xung đột kỹ thuật trên codebase v1.22.0 và chốt kiến trúc Snapshot + Cờ đồng bộ theo nhóm trường.

Người chủ trì: tanmac Trạng thái: HARDENED Slug: example-request

🔒 Các quyết định đã khóa (Locked Decisions)

  • CoreBản chất thực thể: Example Request là kịch bản đầu vào (Input Scenario / Variant) gắn dưới Request gốc để chạy Send thật (giải quyết chuyển nhanh payload JSON/Params phức tạp mà KVPair select không xử lý được, không lưu Response mẫu kiểu Doc/Mock).
  • DataRequest gốc là Default + Nhúng examples[]: Request gốc luôn tự chạy được với vai trò kịch bản mặc định; danh sách Example lưu nhúng trong <req-uuid>.json (Move/Delete/Duplicate trọn bộ, cấp lại UUID cho Example khi Duplicate Request).
  • SyncSnapshot đầy đủ + Cờ đồng bộ theo nhóm trường: Mỗi Example có bảng cờ theo dõi cho các nhóm (url, method, auth, scripts, body, params, path_params, headers, variables). Mặc định khi clone: URL, Method, Auth/AuthEnvs, Scripts bật đồng bộ; phần Input còn lại để độc lập. Bật/tắt tự do trên từng Example; thao tác Sync / Sync All chỉ đẩy các nhóm đang bật đồng bộ (hoặc chọn nhóm lúc Sync).
  • URLTách Base URL và Query Params: Khi URL đồng bộ mà Params độc lập, chỉ đồng bộ phần trước ? (Base URL + cấu trúc :path_param, giữ nguyên value :path_param ở Example); UrlBar ghép động Base URL và Query của kịch bản đang chọn.
  • UXSwitcher trong Editor & Bảo vệ sửa nhầm: Đặt Example Switcher ngay trong RequestEditor (không thêm node con ở Sidebar hay tab riêng ở AppTabBar). Nhóm đang bật đồng bộ hiển thị Linked / Chỉ đọc; muốn sửa riêng thì bỏ tích đồng bộ hoặc bấm "Tách thành Request độc lập". Lưu active_example_id ở UI local (không làm bẩn Git diff) và cache Response theo cặp (requestId, exampleId).
  • ScopeHệ sinh thái đồng bộ: Mở rộng git_merge.go merge examples[] theo id; thêm example_id?: string tùy chọn vào FlowStep (lỗi rõ nếu Example bị xóa); hỗ trợ --example trên hecto run / hecto flow / hecto req (SKILL.md); không import Postman Examples.

🚫 Phương án đã loại bỏ & Lý do (Rejected Options)

  • RejectedLưu cặp Request+Response mẫu kiểu Postman Docs/Mock: Lệch khỏi nhu cầu chạy thử nhiều kịch bản đầu vào và trùng lặp với Mock Server có sẵn.
  • RejectedKhóa cứng vĩnh viễn URL/Method/Auth/Scripts: Không đáp ứng được trường hợp kịch bản rẽ nhánh cần sửa riêng hoặc tách hẳn thành Request độc lập.
  • RejectedSync All ghi đè toàn bộ Request gốc xuống Example: Gây mất dữ liệu Body / Params / Headers của các kịch bản kiểm thử.
  • RejectedHiển thị Example dưới cây Sidebar / Tab riêng: Làm phình cây thư mục TreeNodeRow.vue và dễ dẫn đến sửa nhầm Request gốc qua nhiều tab trùng tên.
  • RejectedLưu active_example_id vào file JSON & Import Postman Examples: Tránh Git diff nhiễu khi chỉ click xem và tránh gượng ép map Response snapshot của Postman.

⚠️ Điểm yếu & Bẫy kỹ thuật đã soi ra (Surviving Scrutiny & Traps)

  • Codebase CrackuseUrlParamsSync.ts & requestStore.ts đang đồng bộ 2 chiều req.url ↔ req.params — phải cắt ranh giới trước/sau ? để tránh Example ghi đè query vào Base URL gốc.
  • Git Mergegit_merge.go chưa có bộ merge 3 chiều theo id cho mảng object lồng nhau — bắt buộc bổ sung để không conflict toàn mảng examples.
  • ParityRequestEditor.vue (resolvedCurlPreview) phải sinh cURL theo đúng Example đang mở; RequestService.Duplicate phải sinh UUID mới cho các Example bên trong.
  • ComplexityMô hình Snapshot + Cờ đồng bộ từng nhóm phức tạp hơn khóa cứng — cần UI hiển thị trạng thái Linked/Unlinked thật rõ ràng để người dùng không nhầm lẫn.
