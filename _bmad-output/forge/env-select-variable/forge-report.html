Biến & KVPair dạng Select Box trong hecto-api

Giải quyết tình trạng chọn đi chọn lại giá trị lặp lại gây mệt và dễ gõ sai khi test API.

Người chủ trì: tanmac Dự án: hecto-api (v1.21.0) Mục tiêu: Làm rõ • Phản biện • Chốt thiết kế Ngày chốt: 2026-11-25

✅ Các quyết định đã khóa (Locked Decisions)

  • Mở rộng trực tiếp trên KVPair: Bổ sung kiểu trường tùy chọn (vd type?: "text" | "select") và options?: string[] (omitempty) trong projects/model/types.go; mặc định là "text" để tương thích ngược hoàn toàn.
  • Áp dụng cho toàn bộ các bảng KVPair: Hỗ trợ trên cả 4 tầng Variables (Collection, Global Env, Folder Global, Folder Env) lẫn Request Params, PathParams, Headers, FormData, URLEncoded — trừ các header tự sinh _isAuto.
  • Điểm chạm chọn nhanh: Chọn 1-click trực tiếp tại VariableHoverPopover.vue (khi hover {{biến}} hoặc :param) và trong bảng KvpEditor.vue / EnvModal.vue, với nút chuyển Text ↔ Select + popover sửa options thu gọn ở cuối ô Value.
  • Kế thừa 4 tầng: options gắn trực tiếp theo từng dòng ở mỗi tầng (để Dev và Prod có thể có danh sách lựa chọn khác nhau). Khi ghi đè qua VariableHoverPopover vào một tầng chưa khai báo options, popover kế thừa danh sách options từ tầng gần nhất đang có.
  • Cấu trúc options: Dùng mảng chuỗi thuần string[] hiển thị qua dropdown list, không thêm trường label riêng.
  • Độ chặt & giá trị ngoài danh sách: Dropdown có dòng + Thêm lựa chọn... ở cuối để nối nhanh option mới ngay tại chỗ mà không phải mở modal. Nếu script (pm.*.set) hoặc CLI hecto ghi một value không nằm trong options, UI giữ nguyên giá trị đó kèm nhãn "(ngoài danh sách)"; đồng thời hỗ trợ dùng {{biến}} lồng bên trong từng option.
  • Lưu trữ thống nhất: Khi chọn option, app ghi thẳng value (và options nếu mới thêm) vào file JSON trên đĩa như cơ chế hiện tại, giữ đồng bộ giữa Desktop UI, API Flow và CLI hecto.

🚫 Các phương án đã loại bỏ & lý do

Option dạng { label, value }: Bị loại vì làm tăng độ phức tạp khi nhập và không cần thiết cho mục tiêu chọn nhanh các chuỗi định sẵn.
Chỉ giới hạn trong 4 tầng Variables: Bị bác bỏ sau phản biện của người dùng — Request Params, PathParams, Headers và Body cũng thường xuyên có các giá trị lặp lại và đã dùng chung model KVPair + component KvpEditor.vue.
Thanh Quick-Switch ghim ngoài Header hoặc chỉ sửa trong Modal: Loại thanh ghim ngoài vì dễ làm rối UI khi nhiều biến; loại việc chỉ sửa trong Modal vì không giảm được thao tác khi đang bấm Send liên tục.
Dropdown khóa cứng tuyệt đối / Combobox nhập tự do: Khóa cứng gây vướng khi thiếu 1 option đột xuất hoặc khi script/CLI ghi đè; combobox tự do dễ lặp lại lỗi gõ nhầm.
Lưu lựa chọn đang chọn ở state cục bộ tách khỏi JSON: Loại bỏ để tránh lệch dữ liệu giữa Desktop UI, API Flow và CLI hecto.

⚠️ Điểm yếu còn lại & bẫy kỹ thuật cần lưu ý khi triển khai

Nhiễu Git diff khi đổi lựa chọn thường xuyên: Vì giá trị đang chọn ghi thẳng vào JSON trong thư mục Collection, team dùng GitAutoSync cần chấp nhận việc đổi dropdown sẽ làm file JSON đổi giống hệt hành vi sửa biến hiện tại.
Rủi ro rụng field type / options trong codebase hiện tại: Bắt buộc phải cập nhật kvEqual & kvToMap trong projects/service/git_merge.go, upsertVariable trong VariableHoverPopover.vue, dirty-check trong EnvModal.vue, và upsertKVPair trong projects/cmd/hecto/main.go (hiện cả 4 nơi đều chỉ giữ 4 field key, value, enabled, description).
Gọn UI trong KvpEditor.vue & EnvModal.vue: Cần giữ nút chuyển Text ↔ Select cực gọn ở cuối ô Value (ẩn nhẹ khi không dùng) để 90% dòng text thường không bị chật chội, đồng thời lưu ý EnvModal.vue đang tự render bảng riêng thay vì dùng KvpEditor.vue.
