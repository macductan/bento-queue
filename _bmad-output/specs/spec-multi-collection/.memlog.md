- (direction) Create technical spec for Multi Collection based on Task 4 in improve.md
- (decision) Collections live under a base collections directory, each as an independent folder containing collection.json and environments/
- (decision) Backward compatibility: preserve existing default collection and auto-migrate config.json with zero data loss
- (decision) DuplicateCollection performs deep copy with newly generated UUIDs for the collection, requests, folders, and environments
- (decision) Deletion safety: deleting the last remaining collection is prohibited; deleting active collection auto-switches to another collection
- (capability) CAP-1: Users can perform full lifecycle CRUD (create, rename, delete, duplicate, list) on independent collections
- (capability) CAP-2: Users can quickly switch the active collection via a switcher UI on AppSidebar/AppHeader
- (capability) CAP-3: Collection state is completely isolated (requests, folders, environments, editor state); unsaved changes are safeguarded before switching
- (capability) CAP-4: System preserves file-based JSON/YAML storage on disk with automatic discovery and backward compatibility for default collection
- (constraint) Data storage strictly file-based JSON/YAML on disk; no SQLite/DB, no login, no cloud sync
- (constraint) Collection switching MUST prompt if isDirty and cleanly reset active editor/response/tree state
- (constraint) Collection directory slug is generated at creation and remains unchanged when renamed (AD-4)
- (non_goal) Cloud sync, remote collaborative sharing, or multi-device sync is out of scope for this phase
- (event) Validation Pass 1 (Coherence) & Pass 2 (Preservation) successful
- (decision) Split into 3 stories: 1. Backend Collection CRUD & backward compatibility, 2. Store isolation & unsaved prompt, 3. Collection switcher UI
- (direction) User clarified: use slug instead of UUID for active_collection, and explicitly distinguish default_collection from active_collection
- (decision) Use directory slug (e.g. 'default', 'ecommerce') as collection identifier in config.json and API calls
- (decision) AppConfig explicitly defines default_collection (fallback/startup collection) and active_collection (current runtime collection); 'default' collection cannot be deleted
- (direction) User clarified: Make slug the primary key of Collection entity, with name/displayName as display name; drop separate collection UUID
- (decision) Collection entity uses slug as sole primary key; name is display name; old collection.json without slug will auto-populate slug from directory name
- (decision) Adopt '<slug>-<uuid>' pattern for collection directory/key to prevent collisions across multiple machines, while 'default' remains 'default'
- (decision) Folder naming convention strictly adopts '<slug>-<UUID>' (e.g. 'auth-8c5d3065-29bc-4408-ba1d-020d79032a88') for collections and child folders
- (direction) User direction: Standardize all new filenames and primary keys to '<slug>-<UUID>' across collections, folders, and requests; no complex legacy migration needed as there are no production users yet
- (decision) System-wide convention adopted: '<slug>-<UUID>' for entity filenames/directories; legacy migration code dropped to keep codebase clean and modern
