# Công cụ CLI độc lập (`hecto`) cho AI Agent, Shared TS Execution Engine qua `goja` và Đồng bộ dữ liệu 3 lớp với Wails Desktop

## Why

Hiện tại `hecto-api` chỉ có thể tương tác thông qua giao diện đồ họa Wails Desktop (`hecto-api`), khiến các AI Coding Agent (Claude Code, Cursor, Antigravity, Windsurf, Cline) và các pipeline tự động hóa/CI không thể đọc cấu trúc API, khởi tạo/cập nhật Request/Folder/Environment hoặc thực thi kiểm thử HTTP Request trực tiếp từ dòng lệnh. Hơn nữa, toàn bộ ~2.300 dòng logic cốt lõi gồm phân giải biến 4 tầng (`resolveHierarchyVariables.ts`), kế thừa xác thực (`auth.ts`), tổng hợp request (`buildExecuteRequest.ts`), phân tích lệnh cURL (`curl.ts`) và bộ chạy kịch bản Pre-request / Post-response (`scriptRunner.ts`) đang nằm 100% ở tầng TypeScript/Vue 3 để phục vụ hiển thị đồng bộ tức thì trên UI; nếu viết lại bộ logic này bằng Go thuần sẽ dẫn đến lệch hành vi giữa CLI và Desktop App (dual-engine drift). Xây dựng binary CLI độc lập `hecto` trong cùng repository (tái sử dụng 100% `model`, `storage`, `service`, `slug`), nhúng bundle `headless-engine.js` chạy trên `goja` (pure Go JS engine), chuẩn hóa ma trận lệnh stateless `--json` kèm lệnh tự khám phá `hecto agent-guide` và cơ chế đồng bộ 3 lớp (Atomic Write + Self-healing Index + Nút Smart Reload trên UI) sẽ biến `hecto-api` thành nền tảng API Client kết hợp liền mạch giữa AI Agent và lập trình viên trên cùng một nguồn dữ liệu đĩa.

## Capabilities

- **CAP-1**
  - **intent:** Hệ thống biên dịch và xuất binary CLI độc lập `hecto` (`projects/cmd/hecto/main.go`) không phụ thuộc vào Wails/GTK/WebKit, có thể cài đặt và chạy độc lập trên môi trường chỉ có terminal/CI nhưng dùng chung 100% cấu trúc lưu trữ và các package `model`, `storage`, `service`, `slug` với ứng dụng Desktop `hecto-api`.
  - **success:** `projects/service/config.go` tách bỏ import trực tiếp `github.com/wailsapp/wails/v2/pkg/runtime` (thay bằng callback tùy chọn `onStartupError` truyền từ `App.startup`). Lệnh `go build -o build/bin/hecto ./cmd/hecto` biên dịch thành công ra binary độc lập không chứa bất kỳ phụ thuộc nào tới `wailsapp` hay thư viện C/GTK/WebKit (`go list -deps ./cmd/hecto` không xuất hiện `github.com/wailsapp/wails/v2`). Binary `hecto` tự động đọc/khởi tạo cùng tệp `config.json` (`{os.UserConfigDir()}/hecto-api/config.json`, hỗ trợ ghi đè qua biến môi trường `HECTO_CONFIG_DIR` hoặc cờ `--data-dir` khi kiểm thử), thiết lập `fs.SetCollectionRoot(targetCollRoot)` ngay sau khi phân giải collection đích, và thao tác trực tiếp trên `collections_root` chuẩn của `hecto-api`.
- **CAP-2**
  - **intent:** CLI `hecto` thực thi trọn vẹn luồng phân giải biến 4 tầng, kế thừa Auth, kế thừa Headers, chạy Pre-request / Post-response Script (`ha.*` / `pm.*`), xây dựng `ExecuteRequest` và phân tích lệnh `curl` bằng chính mã nguồn TypeScript của Frontend thông qua bundle `headless-engine.js` nhúng (`//go:embed`) trên `goja` (pure Go JS engine).
  - **success:** Entrypoint `projects/frontend/src/utils/headless-engine.ts` được đóng gói qua `bun run build:headless` (chạy trước `vite build` trong script `"build"`) thành `projects/engine/headless-engine.js` (được track trong Git để các job Go trên CI biên dịch trực tiếp) và nhúng vào package `hecto-api/engine` chạy trên `github.com/dop251/goja` (kèm polyfill `btoa`/`atob` chuẩn Latin-1 byte-per-rune cho Unicode Basic Auth, `TextEncoder`, `TextDecoder`, `console`). Khi chạy `hecto run <id|path> [--collection <id|name>] [--env <id|name>] [--var K=V]... [--timeout <sec>] [--no-save-env] [--json]`, hệ thống thực thi tuần tự: đồng bộ hai chiều `url`/`params`/`path_params` $\rightarrow$ phân giải biến 4 tầng (`Collection -> Global Env -> Folder Global -> Folder-Env` + ghi đè từ `--var K=V`) $\rightarrow$ chạy Pre-request Script (áp dụng `requestMutations` cùng `envUpdates`, `scopedEnvUpdates`, `scopedAuthUpdates` ngay trong bộ nhớ lên bản sao `collection`/`environments`/`pathFolders`/`allFolders`) $\rightarrow$ phân giải Auth & Headers kế thừa qua `buildExecuteRequest` $\rightarrow$ gửi HTTP request qua `ExecutorService.Send` $\rightarrow$ chạy Post-response Script (nhận ngữ cảnh đã cập nhật từ Pre-request Script) $\rightarrow$ phân giải các khóa sentinel `'__nearest__'`, `'__active__'` cùng tên Folder/Env sang UUID để lưu bền vững `envUpdates`, `scopedEnvUpdates`, `scopedAuthUpdates` vào `collection.json`, `environments/<id>.json`, `_folder.json` (trừ khi truyền `--no-save-env`) và ghi nhận `HistoryService.RecordExecution`, trả về `RunOutput` (`status_code`, `request`, `response`, `script_logs`, `script_error`, `env_updates`).
- **CAP-3**
  - **intent:** Bất kỳ AI Agent hoặc công cụ tự động hóa nào cũng có thể tự khám phá cách sử dụng `hecto` qua lệnh `hecto agent-guide` và giao tiếp qua giao thức Stateless CLI trả về cấu trúc `model.Result` đồng nhất khi truyền cờ `--json`.
  - **success:** Dòng đầu tiên của `hecto --help` (và `hecto -h`) hiển thị chỉ dẫn nổi bật dành cho AI Agent (`🤖 AI AGENT / LLM GUIDE: Run "hecto agent-guide" to print the complete SKILL.md manual...`). Khi chạy `hecto agent-guide`, CLI in trực tiếp nội dung chuẩn `SKILL.md` (nhúng sẵn trong binary qua `//go:embed`) ra `stdout` với đầy đủ frontmatter YAML, quy tắc định danh UUID/Path, bảng tra cứu nhanh toàn bộ lệnh và ví dụ mẫu. CLI cấu hình `slog.Logger` không in thông tin thừa ra `stdout` (`io.Discard` hoặc `os.Stderr` mức `LevelError`) và hỗ trợ đặt cờ (`--json`, `-c`, `--to`, `--set-var`,...) ở cả trước hoặc sau đối số vị trí `<id|path>`. Khi truyền cờ `--json` ở bất kỳ lệnh nào, CLI luôn xuất duy nhất một khối JSON chuẩn `model.Result` (`{ "success": true, "data": ... }` với exit code `0`, hoặc `{ "success": false, "error": { "code": "...", "message": "..." } }` với exit code `1`).
- **CAP-4**
  - **intent:** Người dùng và AI Agent có thể quản lý toàn diện 4 thực thể (`collection`, `env`, `folder`, `req`) thông qua ma trận lệnh trực giao `hecto <entity> <verb>` và nhập nhanh dữ liệu qua `hecto import`, hỗ trợ định danh bằng cả UUID lẫn tên hoặc đường dẫn phân cấp tên.
  - **success:** Hệ thống cung cấp đầy đủ các lệnh:
    - `hecto collection list | get [id|name] | create --name <name> [...] | update <id|name> [...] | delete <id|name> | switch <id|name>` (xóa collection đang active sẽ tự động chuyển `active_collection` về `'default'`).
    - `hecto env list | get <id|name> | create --name <name> [--var K=V]... [--activate] | update <id|name> [--name ...] [--set-var K=V]... [--unset-var K]... | delete <id|name> | activate <id|name|none>` (xóa environment đang active sẽ tự động xóa `active_env_id` trong `collection.json`).
    - `hecto folder list | tree | get <id|path> | create --name <name> [--parent <id|path>] [--var K=V]... [--env-var <env>:<K>=<V>]... [--header K:V]... [--auth ...] | update <id|path> [...] | delete <id|path> | move <id|path> --to <id|path|root>`
    - `hecto req list [--folder <id|path>] | get <id|path> | create --name <name> --method <M> --url <U> [--folder <id|path>] [...] | update <id|path> [...] | delete <id|path> | move <id|path> --to <id|path|root>`
    - `hecto import <file-or-curl> [--collection <id|name>] [--folder <id|path>] [--name <name>]` (nhận diện chuỗi bắt đầu bằng `curl `, hoặc kiểm tra file tồn tại trên đĩa trước khi phân biệt JSON Postman Collection v2.1 hay file chứa lệnh `curl`, hỗ trợ import vào `--folder` và ghi đè `--name`).
    Lệnh `create` khởi tạo và cấu hình đầy đủ thực thể ngay trong 1 bước; lệnh `update` thực hiện **Read-Merge-Write (patch)** dùng `FlagSet.Visit` để chỉ cập nhật các trường được truyền cờ (cho phép truyền chuỗi rỗng `""` để xóa trường mà không làm mất các trường không chỉ định như `scripts`, `auth_envs`, `folder_envs`, `path_params`); chuẩn hóa `--auth-type apikey` thành `'apiKey'`; phân giải tên environment sang UUID trong `--env-var`/`--active-env`; bộ phân giải định danh đọc đầy đủ `model.Request` từ đĩa qua `ReadJSON`, xử lý đường dẫn có dấu `/` thừa hoặc tên chứa `/`, và trả về lỗi `VALIDATION` kèm danh sách UUID nếu phát hiện trùng tên ở cùng một cấp thư mục.
- **CAP-5**
  - **intent:** Ứng dụng Wails Desktop (`hecto-api`) và CLI (`hecto`) hoạt động song song an toàn trên cùng thư mục dữ liệu nhờ cơ chế đồng bộ 3 lớp: Atomic Write ở tầng đĩa, chỉ mục UUID tự chữa lành (`FindByUUID` self-healing & single-walk `GetTree`) ở tầng Go Backend, và nút Reload dữ liệu thông minh (`Smart Data Reload`) kèm chấm báo hiệu `fsnotify` trên tầng UI.
  - **success:** (1) `FileSystem.FindByUUID` kiểm tra `f.Exists(path)` (và kiểm tra sự tồn tại của `_folder.json` nếu `path` là thư mục) khi trúng cache RAM; nếu tệp/thư mục đã bị CLI xóa hoặc `move`, tự động xóa cache cũ (`IndexDelete`) và quét lại `walkFindUUID` để cập nhật đường dẫn mới (đồng thời cập nhật `TestFindByUUID_IndexHit` dùng file thực trên `t.TempDir()`). (2) `CollectionService.GetTree` bỏ lời gọi `IndexRebuild` thừa, cập nhật trực tiếp `IndexSet` cho cả Folder và Request ngay trong 1 lượt duyệt `buildTree`, và `App.ListCollections`/`GetCollectionTree` tự động đồng bộ lại `a.activeCollection` và `a.collRoot` nếu `config.json` thay đổi từ CLI. (3) Wails Backend tích hợp `fsnotify` theo dõi đệ quy `collRoot` (tự động đăng ký đệ quy cả cây thư mục con mới tạo, bỏ qua `.tmp-*`, `.git`, `.history` và lọc bỏ các thao tác tự ghi của chính tiến trình Wails có `defer f.RecordSelfWrite()`), phát sự kiện `collection:external-change` (debounce 300ms) lên Frontend. (4) Trên `AppSidebar.vue`, hiển thị nút Reload dữ liệu riêng biệt (`data-test="sidebar-reload-btn"`) kèm chấm báo hiệu (`data-test="external-change-badge"`) khi có thay đổi ngoài; khi bấm nút hoặc nhấn `Ctrl+R` / `Cmd+R` / `F5` (cập nhật `App.vue` gọi `collectionStore.smartReload()` thay cho `window.location.reload()`), hệ thống thực thi `collectionStore.smartReload()`: giữ nguyên `expandedFolders`, làm mới `envStore` kèm gọi `envStore.syncActiveEnvFromCollection()` sau khi nạp xong, đóng các tab đã bị xóa trên đĩa, cập nhật tên/method tab, tự động tải lại tab Request hoặc Folder đang mở nếu `!isDirty` (cập nhật `FolderEditor.vue` gọi `loadFolderData()` khi nhận `hecto:folder-updated`), và bảo vệ tuyệt đối tab Request hoặc Folder đang gõ dở (`isDirty === true`) kèm thông báo toast cảnh báo.

## Constraints

- **Single Source of Truth cho Execution Engine:** Tuyệt đối không viết lại bản sao logic phân giải biến 4 tầng, kế thừa Auth, `buildExecuteRequest`, `parseCurlCommand` hay `scriptRunner` bằng Go thuần; mọi thay đổi ở `projects/frontend/src/utils/` phải tự động phản ánh vào CLI thông qua `bun run build:headless` và file `projects/engine/headless-engine.js` được track trong Git.
- **Zero-Wails Dependency cho CLI:** Binary `hecto` (`projects/cmd/hecto`) không được import bất kỳ gói nào của `github.com/wailsapp/wails/v2` hoặc phụ thuộc vào thư viện đồ họa hệ thống (`libgtk-3`, `libwebkit2gtk`).
- **Ngữ nghĩa Read-Merge-Write cho `update`:** Mọi lệnh `hecto <entity> update` phải đọc thực thể hiện có từ đĩa, chỉ trộn (merge/patch) các trường có cờ được truyền tường minh trên CLI (nhận biết qua `FlagSet.Visit`), và ghi lại bằng `FileSystem.WriteJSON` nguyên tử; nghiêm cấm ghi đè giá trị rỗng lên các trường không được chỉ định.
- **On-Demand Smart Reload trên UI:** Tuyệt đối không sử dụng `window.location.reload()` (kể cả khi nhấn `Ctrl+R` / `Cmd+R` / `F5` trong `App.vue`) và không tự động gọi `loadTree()` ngầm mỗi khi `fsnotify` bắn sự kiện hoặc khi cửa sổ focus nhằm tránh giật/khựng giao diện và tránh làm mất trạng thái đang soạn thảo.
- **Quy tắc an toàn dữ liệu khi test (Mục 19):** Mọi bài kiểm thử (Go unit test, CLI integration test, Vitest) bắt buộc sử dụng thư mục tạm độc lập (`t.TempDir()`, `--data-dir` / `HECTO_CONFIG_DIR`) hoặc collection `Test-Collection`; nghiêm cấm đọc, sửa hoặc xóa dữ liệu thật của người dùng.

## Non-goals

- Không triển khai giao thức MCP Server chạy nền dài hạn (`hecto mcp` qua stdio/SSE) trong phạm vi đặc tả này.
- Không triển khai lệnh tự động ghi tệp `SKILL.md` cứng vào thư mục cấu hình riêng của từng IDE (`hecto skill install`); AI Agent sử dụng trực tiếp đầu ra chuẩn từ `hecto agent-guide`.
- Không hỗ trợ đồng bộ con trỏ thời gian thực (real-time collaborative cursor) trên cùng một ô nhập liệu đang gõ dở giữa CLI và Desktop UI.

## Success signal

- Từ terminal trên một máy không cần mở giao diện đồ họa, AI Agent chạy `hecto --help` thấy hướng dẫn `hecto agent-guide`, chạy `hecto agent-guide` đọc toàn bộ tài liệu `SKILL.md`, sau đó thực thi chuỗi lệnh:
  1. `hecto folder create --name "AuthFlow" --var "base_url=https://httpbin.org" --json`
  2. `hecto req create --folder "AuthFlow" --name "Login" --method POST --url "{{base_url}}/post" --body-type json --body '{"user":"admin"}' --post-script 'ha.folderVariables.set("token", "secret-jwt")' --json`
  3. `hecto run "AuthFlow/Login" --json`
  Kết quả trả về JSON `model.Result` với `success: true`, `data.status_code: 200`, và biến `token = "secret-jwt"` (từ khóa mặc định `'__nearest__'`) được lưu bền vững vào `_folder.json` của thư mục `AuthFlow`.
- Khi ứng dụng Desktop `hecto-api` đang mở song song: ngay sau khi CLI thực thi các lệnh trên, nút Reload trên Sidebar hiện chấm báo hiệu thay đổi ngoài; người dùng bấm nút Reload (hoặc nhấn `Ctrl+R` / `F5`) thấy thư mục `AuthFlow` và request `Login` xuất hiện ngay trên cây thư mục mà các nhánh đang mở (`expandedFolders`) và các tab Request/Folder đang gõ dở (`isDirty = true`) vẫn được giữ nguyên vẹn.
- 100% bài kiểm thử backend (`go test ./...`), CLI integration tests, và frontend (`bun run type-check`, `bun run test`) vượt qua an toàn tuyệt đối.
