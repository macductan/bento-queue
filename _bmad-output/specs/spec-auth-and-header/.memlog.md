- (direction) Create technical spec for Auth and Header feature group from improve.md (items 6, 7, 8, 9)
- (decision) Supports common auth types: Inherit from parent, No Auth, Bearer Token, Basic Auth, API Key.
- (decision) Child request headers override folder headers if keys match (case-insensitive).
- (decision) Default headers include inherited headers (from folder) and auto-generated headers (e.g. Content-Type). They are sent with request but can be hidden in UI to avoid clutter.
- (capability) CAP-1: Users can configure Auth at both folder and request levels, supporting Inherit, No Auth, Bearer Token, Basic Auth, and API Key.
- (capability) CAP-2: Users can configure common headers at folder level which are inherited by child requests.
- (capability) CAP-3: Users can toggle the visibility of default headers (inherited + auto-generated) in the request view to keep the UI clean.
- (constraint) Data storage format remains file-based JSON/YAML on disk (no DB).
- (constraint) Child request headers MUST override parent folder headers case-insensitively when conflicts occur.
- (non_goal) Supporting complex OAuth 2.0 flows (e.g., login windows, PKCE) is out of scope for this phase; only simple token input is supported if OAuth is added.
