- (capability) CAP-1: Lưu trữ & quản lý thực thể Flow và FlowFolder độc lập tại <collection>/flows/ (tách biệt khỏi cây Request trong CollectionService.buildTree), hỗ trợ FlowService CRUD/Tree/Move/Reorder/Duplicate, bộ phân giải định danh UUID/Path và đồng bộ Git 3-Way Merge.
- (capability) CAP-2: Nâng cấp ExecutorService.Send hỗ trợ bắn nhiều HTTP Request đồng thời (thay cờ đơn inflight bằng activeCancels map, Abort hủy toàn bộ request đang bay) và hỗ trợ cấu hình TimeoutMs trên từng model.ExecuteRequest.
- (capability) CAP-3: Bộ máy thực thi Flow (Shared FlowRunner trong headless-engine.ts & projects/engine) hỗ trợ bước Thin Pointer (tái sử dụng 100% biến 4 tầng, Auth Inheritance, Pre/Post Script của Request gốc), chạy Tuần tự, Hàng Song song (gom cập nhật biến sau khi hàng hoàn tất mới ghi đĩa 1 lần), Rẽ nhánh 3 chế độ (Thành công, Khi Lỗi, Điều kiện tùy chỉnh 3 ô), phán quyết Passed/Failed chuẩn xác và giới hạn max_steps.
- (capability) CAP-4: Chuyển đổi không gian làm việc [ APIs | Flows ] giữ nguyên bố cục 2 cột (Sidebar trái quản lý cây Flow Folder/Flow có tìm kiếm, kéo-thả, CRUD + ContentArea phải hiển thị FlowEditor) và tích hợp vào luồng smartReload().
- (capability) CAP-5: Sơ đồ khối tự căn bố cục (Structured Flowchart) theo quy tắc 2 trục vuông góc tự động + nút đảo hướng toàn cục [ ↕ Dọc | ↔ Ngang ], thêm bước qua Searchable Request Picker + kéo-thả khối, và Step Inspector Panel (tái sử dụng ResponseViewer) kèm nút 'Mở Request gốc ↗' nhảy sang chế độ APIs.
- (capability) CAP-6: Mở rộng CLI độc lập hecto với hệ lệnh trực giao hecto flow (list, tree, get, create, update, delete, move, run, folder-create/update/delete/move) trả về chuẩn model.Result khi dùng --json và cập nhật SKILL.md (hecto agent-guide).
- (constraint) Thin-Pointer Step & Không tạo biến/script cấp Flow/Step: FlowStep chỉ lưu { id, request_id, enabled, timeout_ms? }, tái sử dụng 100% cơ chế giải biến 4 tầng, Auth Inheritance và Pre/Post Script của Request gốc; FlowFolder chỉ lưu { id, name, order } thuần phân loại, không chứa Variables/Auth/Headers riêng.
- (constraint) Quy tắc bố cục 2 trục vuông góc tự động (Orthogonal 2-Axis Structured Flowchart): Luồng nối tiếp đi theo trục chính, Hàng Song song (||) và Nhánh rẽ (↙ ↘) bắt buộc bung theo trục vuông góc; chỉ đảo hướng ở cấp toàn sơ đồ [ ↕ Dọc | ↔ Ngang ], nghiêm cấm cho phép từng bước tự chọn hướng ngang/dọc lẻ tẻ gây đè khối.
- (constraint) Chống Race Condition khi ghi biến ở Hàng Song song: Khi chạy đồng thời nhiều Request trong một Hàng Song song, nghiêm cấm ghi trực tiếp biến xuống đĩa trong lúc từng request lẻ đang kết thúc; phải đợi cả hàng kết thúc rồi gom tuần tự envUpdates, scopedEnvUpdates, scopedAuthUpdates theo thứ tự cột từ trái sang phải (hoặc trên xuống dưới) và ghi đĩa đúng 1 lần.
- (constraint) Single Source of Truth cho đánh giá điều kiện nhánh & phán quyết Step: Bộ hàm đánh giá kết quả Step (Passed/Failed) và điều kiện rẽ nhánh 3 chế độ (Success / Error / Custom 3-box) phải viết 1 lần tại projects/frontend/src/utils/ và đóng gói vào headless-engine.js để cả Wails UI và CLI hecto flow run dùng chung.
