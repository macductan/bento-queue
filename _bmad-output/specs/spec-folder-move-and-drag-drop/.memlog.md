- (direction) User requested technical spec for Folder Move & HTML5 Drag and Drop in Sidebar Collection Tree across Go/Wails backend, Vue 3/Pinia frontend, and test suites.
- (decision) Add CollectionService.MoveFolder(rootPath, folderID, targetFolderID string) model.Result and Wails binding App.MoveFolder(folderID, targetFolderID string) model.Result with changelog recording.
- (constraint) Cycle detection in backend and frontend: forbid moving a folder into itself (folderID == targetFolderID) or into any of its descendant subfolders (targetDir under srcPath).
- (decision) Support moving folder to collection root when targetFolderID == ''; handle destination path collision on disk via fallback to slug.FolderDir(folderID) or returning validation error if target path already exists; treat moving to current parent as no-op success.
- (decision) Update storage.FileSystem in-memory index on folder move by remapping all entries under old folder prefix to the new folder path (IndexUpdatePrefix or prefix remap) so nested requests and subfolders remain immediately resolvable via FindByUUID.
- (capability) CAP-1: Backend MoveFolder Service & Wails Binding - move physical folder directory and nested contents on disk, validate cycle/bounds/collisions, and update UUID-to-path index for the folder and all descendants.
- (capability) CAP-2: Pinia CollectionStore moveFolder & Drag-Drop State - provide moveFolder(id, targetFolderId) action in collectionStore that calls MoveFolder, reloads tree, expands target folder path, shows toast, and provides helper to check valid drop targets (preventing self/descendant cycles and redundant same-parent moves).
- (capability) CAP-3: Context Menu 'Di chuyển tới ▸' for Folders - add Move-to submenu on folder context menu in TreeContextMenu.vue, filtering out or disabling the folder itself and all its descendant folders while allowing move to Collection Root or valid folders.
- (capability) CAP-4: HTML5 Drag & Drop in Sidebar Collection Tree - support dragging Request and Folder rows in TreeNodeRow.vue (disabled while inline renaming), visual drop-zone highlighting on target folders and Collection Root drop zone in AppSidebar.vue, and UI-level blocking of invalid drops (cycles, self-drop).
- (capability) CAP-5: Automated Verification & Test Coverage - unit tests in service/collection_test.go (root move, nested move, cycle detection, index prefix update, invalid/collision guards) and Vitest component/store tests in frontend plus clean vue-tsc type-check.
