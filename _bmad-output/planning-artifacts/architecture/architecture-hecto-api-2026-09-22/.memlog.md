- (decision) Paradigm direction: split by responsibility. Go backend owns CRUD (file I/O for collections, requests, environments) + HTTP execution (send request, receive response). Vue frontend owns presentation + interaction logic — gets data from Go, renders, handles form/tab/UI state. Wails bindings = use-case-level API, not raw file I/O. Aligns with Hướng C.
- (decision) Variable substitution: Vue owns entirely. Go returns env variable map via CRUD. Vue parses {{...}} for preview highlighting AND resolves variables to build the final request. Go receives a fully resolved request (URL, headers, body — no {{...}} remaining) and just executes net/http. No substitution logic in Go. File on disk always stores raw {{...}} templates (FR-12 preserved). Prevents duplication of parse logic across boundary.
- (decision) Wails binding contract: entity-oriented CRUD. Each entity (Request, Folder, Environment, Collection) gets explicit, small functions — GetRequest, SaveRequest, DeleteRequest, etc. Plus SendRequest for execution, ImportPostman for import, OpenFileDialog for native dialogs. No action-dispatch pattern. Each binding = one operation, clear name, clear input/output. Prevents ambiguity about what each binding does.
- (decision) Go internal structure: package-per-layer. app.go = thin Wails adapter (delegates to services). service/ = business logic (request, environment, collection, executor, importer). storage/ = file I/O abstraction (filesystem.go). model/ = shared data structs. Services testable without Wails context; storage mockable for service tests. Prevents coupling Wails lifecycle into business logic.
- (decision) Vue state management: Pinia stores. Stores split by domain: collectionStore (tree, active request ref), requestStore (form state of active request), environmentStore (env list, active env, variables map), responseStore (current response), uiStore (tabs, modals, toasts). Each store calls Wails bindings for CRUD. Components read stores + dispatch actions. Prevents scattered state across components.
- (decision) Error handling: structured Result type. Go returns Result{Success, Data, Error} where Error has Code + Message. Error codes: NOT_FOUND, VALIDATION, IO_ERROR, PARSE_ERROR, CONNECTION_ERROR, etc. Vue switches on error.code to display appropriate UI treatment (toast, inline error, error state). All Wails bindings return Result — consistent contract. Prevents Vue from guessing error types from message strings.
- (decision) Entity identity: UUID inside JSON file. Every request, folder, and environment file contains a stable UUID field. Filename on disk is human-readable slug derived from name (for Git-friendliness). Rename/move does not change UUID — Vue keeps stable references. Go generates UUID on create. Convention: slug-from-name.json for requests, folder metadata in folder's own meta file. Prevents broken references on rename/move operations.
- (decision) Collection root: OS-specific app data directory. Linux ~/.config/hecto-api/collections/default/, macOS ~/Library/Application Support/hecto-api/collections/default/, Windows %APPDATA%/hecto-api/collections/default/. Go uses os.UserConfigDir() or equivalent. v1 = single default collection. Storage layout inside already defined by product brief. Path stored in app config for future multi-collection support.
- (decision) Frontend language: TypeScript. Wails v2 auto-generates TS bindings from Go structs — gives type safety when calling Go methods from Vue. Pinia stores + Vue components in TypeScript. Matches the structured approach (layered Go, Pinia stores, Result type errors).
